# API-контракт

## Архитектура

Система состоит из двух сервисов:

- **Service Users** — регистрация, вход, профили, роли и подписки. Хранит пользователей, роли, связи пользователей с ролями и подписки.
- **Service Messages** — сообщения, ленты и реакции. Хранит сообщения и реакции.

Для защищённых запросов передаётся заголовок `Authorization: Bearer <token>`. Текущий пользователь определяется по токену; `user_id` и автор сообщения не принимаются от клиента, если их можно получить из токена.

Роли могут сочетаться. При регистрации выдаётся базовая роль `user`.

## Общие ошибки

Ошибки возвращаются в формате:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Проверьте переданные данные"
  }
}
```

| HTTP | Значение |
|---|---|
| `400` | Некорректный запрос |
| `401` | Нет действительного токена или неверные учётные данные |
| `403` | Недостаточно прав |
| `404` | Пользователь или сообщение не найдены |
| `409` | Конфликт, например занятый email или повторная подписка |
| `422` | Данные не прошли проверку |
| `503` | Зависимый сервис временно недоступен |

## Service Users

Базовый путь: `/api/v1`.

| Метод и путь | Доступ | Назначение | Успех |
|---|---|---|---|
| `POST /auth/register` | Гость | Регистрация, выдача роли `user` | `201` |
| `POST /auth/login` | Гость | Вход и получение токена | `200` |
| `GET /users/me` | `user` | Получить свой профиль | `200` |
| `PATCH /users/me` | `user` | Изменить имя, фамилию или телефон | `200` |
| `GET /users/{id}` | Гость | Получить публичный профиль | `200` |
| `GET /users?role=producer` | `user` | Найти пользователей по роли | `200` |
| `PUT /users/me/subscriptions/{producerId}` | `subscriber` | Подписаться на автора | `204` |
| `DELETE /users/me/subscriptions/{producerId}` | `subscriber` | Отписаться от автора | `204` |
| `GET /users/me/subscriptions` | `subscriber` | Список моих подписок | `200` |
| `GET /users/{id}/subscribers` | `producer` | Список подписчиков автора | `200` |
| `GET /roles` | `administrator` | Список ролей | `200` |
| `POST /users/{id}/roles` | `administrator` | Выдать пользователю роль | `200` |
| `DELETE /users/{id}/roles/{roleName}` | `administrator` | Забрать роль | `200` |
| `DELETE /users/{id}` | `administrator` | Удалить пользователя | `204` |

### Регистрация — `POST /api/v1/auth/register`

Запрос:

```json
{
  "first_name": "Анна",
  "last_name": "Иванова",
  "email": "anna@example.com",
  "phone_number": "+70000000001",
  "password": "secret123"
}
```

Ответ `201 Created`:

```json
{
  "user": {
    "id": 1,
    "first_name": "Анна",
    "last_name": "Иванова",
    "email": "anna@example.com",
    "phone_number": "+70000000001",
    "roles": ["user"]
  },
  "token": "<access-token>"
}
```

Пароль в ответе не возвращается. Email или телефон уже заняты — `409`; неверные поля — `422`.

### Вход — `POST /api/v1/auth/login`

Запрос: `{ "email": "anna@example.com", "password": "secret123" }`.
Ответ `200`: `{ "token": "<access-token>", "user": { "id": 1, "roles": ["user"] } }`.
Неверные учётные данные — `401`.

### Подписка — `PUT /api/v1/users/me/subscriptions/{producerId}`

Тело не требуется. Ответ `204 No Content`. Несуществующий автор — `404`; подписка на себя — `422`; повторная подписка не создаёт дубликат и также возвращает `204`.

## Service Messages

Базовый путь: `/api/v1`.

| Метод и путь | Доступ | Назначение | Успех |
|---|---|---|---|
| `POST /messages` | `producer` | Опубликовать сообщение | `201` |
| `GET /messages/{id}` | Гость | Получить сообщение | `200` |
| `GET /messages` | Гость | Получить общую ленту | `200` |
| `GET /messages?author_id={id}` | Гость | Получить сообщения автора | `200` |
| `GET /feed` | `subscriber` | Получить ленту подписок | `200` |
| `PATCH /messages/{id}` | Автор сообщения | Изменить текст | `200` |
| `DELETE /messages/{id}` | Автор или `administrator` | Удалить сообщение | `204` |
| `PUT /messages/{id}/reaction` | `user` | Добавить или изменить свою реакцию | `200` |
| `DELETE /messages/{id}/reaction` | `user` | Удалить свою реакцию | `204` |
| `GET /messages/{id}/reactions` | Гость | Получить счётчики реакций | `200` |

### Публикация — `POST /api/v1/messages`

Запрос:

```json
{ "text": "Открытая лекция начнётся в пятницу." }
```

Ответ `201 Created`:

```json
{
  "id": 10,
  "author_id": 1,
  "text": "Открытая лекция начнётся в пятницу.",
  "created_at": "2026-11-26T12:00:00Z"
}
```

`author_id` берётся из токена. Пользователь без роли `producer` получает `403`.

### Лента подписок — `GET /api/v1/feed?page=1&size=20`

Требуется токен пользователя с ролью `subscriber`. Ответ `200` содержит сообщения авторов, на которых подписан пользователь, отсортированные от новых к старым:

```json
{
  "items": [
    {
      "id": 10,
      "author_id": 2,
      "text": "Открытая лекция начнётся в пятницу.",
      "created_at": "2026-11-26T12:00:00Z",
      "reactions": { "total": 2, "by_type": { "like": 1, "heart": 1 } }
    }
  ],
  "page": 1,
  "size": 20,
  "total": 1
}
```

Если подписок нет, возвращается `200` с пустым `items`.

### Реакция — `PUT /api/v1/messages/{id}/reaction`

Запрос: `{ "type": "heart" }`. Ответ `200` содержит выбранную реакцию и новые счётчики. Допустимые типы: `like`, `dislike`, `heart`, `laugh`, `wow`, `sad`. Повторный запрос меняет реакцию пользователя, а не создаёт вторую. Сообщение не найдено — `404`; неверный тип — `422`.

## Взаимодействие сервисов при получении ленты

1. Клиент вызывает `GET /api/v1/feed` в Service Messages с пользовательским токеном.
2. Messages проверяет токен и получает `user_id`.
3. Messages запрашивает у Users список `producer_id` для этого пользователя.
4. Messages выбирает сообщения этих авторов, сортирует и возвращает страницу.
5. Если Users недоступен, Messages отвечает `503`.

Внутренний запрос Users: `GET /internal/users/{userId}/subscriptions`, ответ `{ "producer_ids": [2, 3] }`. Внутренний маршрут доступен только сервисам.
